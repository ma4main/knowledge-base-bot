# Telegram-бот самообновляемой базы знаний

Бот для команды, у которой знания живут в рабочих чатах: как отвечать клиенту,
какие сейчас тарифы, что делать, когда «всё упало». Он отвечает сотрудникам на
вопросы по базе, записывает в неё то, что ему диктуют, и сам вычитывает рабочие
чаты по ночам. База знаний при этом остаётся папкой обычных Markdown-файлов в
git-репозитории: её можно читать, править и ревьюить без бота.

Это готовый к развёртыванию продукт с демонстрационной базой вымышленного
агентства «Маяк». Чтобы запустить его для своей команды, нужен сервер с Docker,
токен Telegram-бота и ключ OpenRouter. Инструкция: [`docs/SETUP.md`](docs/SETUP.md).

Демонстрационная база целиком синтетическая: люди, ники, тарифы, цифры и клиентские
случаи придуманы для примера.

> **Рабочий репозиторий должен быть приватным.** Бот раз в сутки отправляет в свой
> репозиторий поток рабочих чатов (`chats-live/`), загруженные файлы и снимок
> состояния с именами и ролями сотрудников. Этот репозиторий — только исходники
> и демонстрация: для своей команды создайте отдельную приватную копию и не
> подключайте бота к публичному репозиторию.

## Что умеет

- **Отвечает по базе, и только по ней.** Модель получает каталог заголовков и сама
  выбирает, какие единицы прочитать. Чего в базе нет, бот честно называет
  отсутствующим и подсказывает, кто в команде за это отвечает.
- **Подстраивает формат под тип вопроса.** Факт: три строки. Разбор ситуации:
  диагностика по шагам. Возражение клиента: суть плюс готовая фраза, которую бот
  сверяет с текстом базы, прежде чем отдать.
- **Пишет в базу с подтверждением автора.** «Запомни: съём позиций теперь в 14:00»,
  кнопка «Внести в базу», пересланное сообщение или тег бота в рабочем чате. Бот
  подбирает единицу, показывает, как именно запишет, и ждёт «верно» от автора.
  Запись уходит в git одним коммитом с подписью.
- **Слушает рабочие чаты и разбирает их ночью.** Записывает новое с пометкой
  «не подтверждено», рискованное помечает на перепроверку, спорное кладёт в очередь
  руководителю. Всё записанное автоматом попадает в недельный отчёт с кнопкой отката.
- **Хранит состояние, а не ленту событий.** Единица, где значение меняется, ведёт
  блоки «Сейчас» и «Было раньше»: новый факт заменяет строку, старое значение
  уезжает в историю с датой.
- **Библиотека файлов и ссылок.** Презентации, прайсы, регламенты и рабочие ссылки
  бот отдаёт по запросу своими словами.
- **Роли и управление из меню.** Менеджер спрашивает и диктует; руководитель выдаёт
  доступы, выбирает чаты для записи, меняет модель, откатывает автозаписи.
  Никаких SSH для повседневного владения.
- **Работает без присмотра.** Переключается на запасную модель, перезапускает себя
  при зависшей связи, следит за диском и git, пишет руководителям только по делу.

## Как это устроено

```
Telegram ──► бот (один Python-процесс в Docker)
               │
               ├── отвечает: системный промпт + каталог базы ──► модель через OpenRouter
               │                                  инструменты: прочитать единицу, поиск, файлы
               │
               ├── пишет: правка единицы ──► коммит ──► git push
               │
               └── слушает: рабочие чаты ──► ночной разбор ──► автозапись + отчёт

git-репозиторий = база знаний (knowledge/*.md) + файлы + поток чатов + код бота
```

Подробнее: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Структура репозитория

| Папка | Что это | Кто пишет |
|---|---|---|
| `knowledge/` | база знаний: единицы по разделам, каталог `INDEX.md`, люди `PEOPLE.md`, ссылки `LINKS.md`, профиль компании `_config.json` | бот по подтверждению автора; ночной разбор; человек руками |
| `files/` | библиотека файлов, которые бот отдаёт сотрудникам | бот (загрузка через Telegram) или человек |
| `chats-live/` | поток рабочих чатов, которые бот слушает | только бот |
| `bot-state/` | суточный снимок состояния бота: роли, чаты, модель | только бот |
| `bot/` | код бота, Dockerfile, docker-compose, проверки | разработчик |
| `docs/` | документация | разработчик |

## Ключевые принципы

- **Достоверность.** Каждое утверждение в базе прослеживается до человека, который
  его продиктовал, или до сообщения в чате. Шапку единицы (id, дата, источник)
  собирает код, а не модель.
- **Актуальность.** У единицы есть дата и статус (`actual` / `needs-check` /
  `outdated`). Меняющееся во времени помечается на перепроверку, прежние значения
  сохраняются в блоке «Было раньше».
- **Человек решает.** Автомат никогда не удаляет и не переписывает существующий
  текст. Всё, что он записал сам, видно в отчёте и откатывается одной кнопкой.
- **Безопасность.** Секреты только в `.env` на сервере. Из потока чатов код
  вычищает телефоны, почты и чужие домены до того, как текст увидит модель.
  Переписка сотрудников с ботом в git не попадает.

## Стоимость и пределы

- Модели через OpenRouter: единицы долларов в месяц на команду из десятка человек.
  Главный рычаг цены: кэш префикса у провайдера (каталог базы идёт в каждый запрос).
- Сервер: любой минимальный VPS, 1 vCPU и 1 ГБ памяти достаточно.
- Предел базы без доработок: 300–400 единиц. Дальше нужен поиск по смыслу вместо
  каталога в промпте. Подробнее: [`docs/SCALING.md`](docs/SCALING.md).
