# Конфигурация

Две точки настройки: секреты и параметры процесса в `bot/.env`, профиль компании
в `knowledge/_config.json`.

## 1. `bot/.env`

Образец: `bot/.env.example`. Сам `.env` в git не попадает. Заполняется скриптом
`bot/set-secrets.sh` или руками.

| Переменная | Обязательна | По умолчанию | Что делает |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | | токен от BotFather |
| `OPENROUTER_API_KEY` | да | | ключ OpenRouter, на аккаунте нужен баланс |
| `OPENROUTER_MODEL` | нет | `google/gemini-3.7-flash` | стартовая модель; после первого запуска берётся из `state.json`, меняется из меню |
| `OPENROUTER_MODEL_FALLBACKS` | нет | см. `config.py` | запасные модели через запятую; `none` отключает |
| `CLASSIFIER_MODEL` | нет | `google/gemini-3.5-flash-lite` | модель классификатора типа запроса и сверки фразы |
| `CLIENT_PHRASE_AUDIT` | нет | `1` | сверять фразу для клиента с текстом базы |
| `CACHE_TTL` | нет | `1h` | TTL кэша префикса у провайдера: `1h` или `5m` |
| `LEADER_IDS` | нет | | числовые Telegram ID первых руководителей; импорт один раз |
| `MANAGER_IDS`, `MANAGER_USERNAMES` | нет | | сотрудники, заданные на сервере; лучше оставить пустыми и выдавать доступ из бота |
| `KB_ROOT`, `DATA_DIR` | нет | подставляет compose | путь к клону базы и к папке данных |
| `MAX_TOOL_ITERATIONS` | нет | `6` | сколько раз подряд модель может звать инструменты |
| `REQUEST_TIMEOUT` | нет | `120` | секунд ждём ответ модели |
| `LOG_LEVEL` | нет | `INFO` | |
| `COMPOSE_PROJECT_NAME` | нет | `bot` | имя compose-проекта, если на хосте уже есть проект `bot` |

Часовой пояс контейнера задаётся в `bot/docker-compose.yml` (`TZ`). Все расписания
(ночной разбор в 21:00, отчёт в понедельник в 10:00) считаются в нём.

## 2. `knowledge/_config.json`

Профиль компании. Бот читает его при старте и подставляет в промпты, меню и
классификатор, а также берёт из него список разделов и диапазоны id.

```json
{
  "company": "Маяк",
  "department": "отдел аккаунтинга",
  "audience": "аккаунт-менеджеры",
  "products": {
    "Трафик": "продвижение сайтов в поиске: позиции, посещаемость, семантика",
    "Карты": "продвижение компаний в геосервисах: карточки, отзывы, показы"
  },
  "sections": {
    "produkt": {
      "title": "Продукт",
      "ids": [100, 199],
      "description": "как работают услуги: механика, сроки, ограничения"
    }
  },
  "examples": {
    "question": "какой тариф на Карты",
    "file": "пришли презентацию по Картам",
    "link": "дай ссылку на зум"
  }
}
```

| Поле | Что значит |
|---|---|
| `company` | название компании; попадает в системный промпт и приветствие |
| `department`, `audience` | кому бот отвечает; формулировки в промптах |
| `products` | продукты и их короткое описание. Если продуктов больше одного и вопрос не уточняет какой, бот спрашивает, а не выбирает сам. Значение `product` в шапке единицы берётся из этого списка или равно `общее` |
| `sections` | разделы базы. Ключ совпадает с именем папки в `knowledge/` и полем `section` в шапке единицы. `title` показывается в меню и отчётах, `ids` задаёт диапазон номеров новых единиц, `description` помогает модели выбрать раздел для новой единицы. Необязательное поле `product` привязывает раздел к одному продукту: новые единицы в нём получают этот `product` в шапке, иначе `общее` |
| `examples` | примеры запросов для подсказок в меню и промпте классификатора |

После правки файла перезапустите контейнер: `docker compose restart`.

## 3. Что ещё настраивается в коде

Редко нужные константы живут рядом с логикой и описаны в [`../bot/README.md`](../bot/README.md):
лимит автозаписей в сутки, срок жизни очереди и черновиков, порог самоснятия
оговорки «не подтверждено», размер кэша ответов, пороги сигналов о диске.
