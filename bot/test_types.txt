# Регрессия классификатора: «вопрос => каким типом он должен быть распознан».
#
# Зачем: формат ответа выбирается по типу запроса (факт — коротко, разбор
# ситуации — playbook, возражение — суть плюс готовая фраза клиенту). Значит
# ошибка НА ВХОДЕ портит весь ответ, и увидеть её в обычных тестах нельзя: бот
# при этом «работает». Здесь она измеряется числом — как route_check.py измеряет
# маршрутизацию правок.
#
# Формат: вопрос => ТИП (ФАКТ / РАЗБОР / ВОЗРАЖЕНИЕ / ФАЙЛ / ПРОЧЕЕ).
#         Через запятую — несколько допустимых типов; так помечены случаи, где
#         спор по существу, а не ошибка классификатора (см. раздел «спорные»).
# Прогон:  docker compose run --rm kb-bot python type_check.py
#
# Пополнять реальными вопросами менеджеров из transcripts.jsonl — там у каждой
# записи лежит поле kind, то есть видно, что бот решил на настоящем вопросе.
