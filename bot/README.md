# Код бота: карта модулей и правила

Один Python-процесс на aiogram 3, без базы данных и без cron. Логика описана в
[`docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md), проектные решения и их причины
в [`docs/DESIGN-DECISIONS.md`](../docs/DESIGN-DECISIONS.md). Здесь то, что нужно,
чтобы ориентироваться в коде и не сломать инварианты.

## Карта модулей

### Ядро: база знаний и ответ

| Модуль | За что отвечает |
|---|---|
| `kb.py` | загрузка базы в память, каталог, поиск по словам, отпечаток файлов на диске |
| `kbconfig.py` | профиль компании и разделы из `knowledge/_config.json` |
| `frontmatter.py` | единственный разбор YAML-шапки единицы |
| `prompts.py` | системный промпт и сборка кэшируемого префикса |
| `agent.py` | агентский цикл: тип запроса, выбор единиц по каталогу, инструменты, ответ |
| `tools.py` | инструменты модели: чтение единиц, поиск, файлы; только чтение |
| `qtype.py` | классификатор типа запроса и намерения, формат ответа под тип |
| `factcheck.py` | сверка фразы для клиента с текстом единиц |
| `answer_cache.py` | кэш ответов по вопросу и единицам |
| `formatting.py`, `ui.py` | приведение ответа к Telegram: разбиение, разметка, кнопки |
| `safety.py` | обращение с недоверенным текстом: чужие слова как данные |
| `people.py`, `links.py`, `files_lib.py`, `doc_text.py` | справочник людей, ссылки, библиотека файлов, извлечение текста из pdf и docx |

| `type_check.py` | да | точность классификатора на `test_types.txt` |

## Локальный запуск

```bash
python -m venv .venv && .venv/bin/pip install -r bot/requirements.txt
cp bot/.env.example bot/.env      # заполнить токен, ключ и LEADER_IDS
cd bot && python selfcheck.py     # без ключей
python main.py                    # данные бота лягут в bot/data/, папка в .gitignore
```

Образ для сервера: `python:3.12-slim`, пакеты зафиксированы в `requirements.txt`.

## Правила работы с кодом

**Провайдер и адаптеры.** Всё выше адаптера (agent, prompts, tools, история диалога)
говорит на нейтральных типах. Wire-специфика провайдера живёт в `llm/`. Если смена
провайдера требует правок вне `llm/`, граница дырявая.

**Асинхронность.** Синхронный ввод-вывод (subprocess, сеть, блокирующий диск) не
зовётся из корутины напрямую, а оборачивается в `asyncio.to_thread` на уровне
самого класса. Любой обработчик потенциально конкурентный, даже для одного
пользователя: разделяемое состояние защищено блокировкой на ключ (`USER_LOCKS`),
запись в базу под одним `KB_WRITE_LOCK`.

**Роутеры.** Один Router на функциональную область. Корневой роутер агрегирует и не
содержит обработчиков, ловящих всё: aiogram сначала прогоняет обработчики самого
роутера и лишь потом вложенные, и catch-all в корне молча перехватит команды
вынесенных модулей. Порядок включения роутеров равен порядку диспетчеризации,
модуль с catch-all включается последним. Это проверяется в `selfcheck`.

**Общее состояние.** Всё, что живёт в пределах процесса, в `botstate.py`, один
экземпляр на бота. Модуль, заведший свою копию `PENDING_*`, не падает, кнопка
«работает», просто не находит своё. Тождество объектов проверяется в `selfcheck`.

**Формат ядра.** Frontmatter разбирает ровно одна функция. Шапку новой единицы
(id, дата, источник) собирает код, не модель. Счётчики каталога поддерживает код.

**Безопасность.** Пользовательский текст в HTML экранируется и отправляется с
запасным вариантом без разметки. Пути к файлам проверяются на выход за пределы
папки. Чужой текст в промпте помечается как данные (`safety.as_data`). Секреты
только в `.env`.

**Комментарии.** Код без хроники: что и почему устроено так, описано в `docs/`.
В коде остаются только пояснения, без которых строку нельзя прочитать:
ограничения Telegram API, гонки, обходные пути.

**Тесты.** `selfcheck.py` гоняется без ключей и сети. Любой новый критичный путь
получает проверку в нём. После переносов кода обязательно `pyflakes`: selfcheck
не ловит неопределённые имена в необойдённых ветках.
