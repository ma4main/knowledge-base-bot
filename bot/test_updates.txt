# Регрессия маршрутизации правок: «апдейт => куда он должен лечь».
#
# Зачем: главная ошибка редактора — положить апдейт не в ту единицу (например,
# правило про отчёты — в единицу про передачу клиента). Такие ошибки не видны
# в обычных тестах, потому что бот при этом «работает». Здесь они измеряются числом.
#
# Формат: текст апдейта => ожидаемые kb-id через запятую (любой из них — попадание)
#         или НОВАЯ, если правильный ответ — создать новую единицу.
# Прогон:  docker compose run --rm kb-bot python route_check.py

# --- Однозначные попадания в существующую единицу ---
первые сдвиги по Трафику теперь через 4–6 недель, а не 3–4 => kb-101
на отзывы теперь отвечаем в течение одного рабочего дня, а не двух => kb-102
если просадка в одном срезе, а сайт в порядке — ждём два среза, а не один => kb-103
тариф Трафик «Старт» с ноября 27 000 рублей => kb-301
срок возврата теперь 7 рабочих дней вместо 10 => kb-302
отсрочка по оплате теперь 3 рабочих дня, а не 5 => kb-303
новичку на третьей неделе даём 5 проектов по Картам, а не 3 => kb-401
планёрка отдела переносится на вторник, 11:00 => kb-402
бриф-карта теперь заполняется до первого созвона, а не до оплаты => kb-403

# --- Темы на стыке: допустимо несколько единиц (тут бот спрашивает человека) ---
скидка 5% за оплату трёх месяцев вперёд отменена => kb-202, kb-301
срез позиций по Трафику переносим со среды на четверг => kb-402, kb-101
шаблон письма о просадке после обновления поиска: добавили строку про следующий срез => kb-203, kb-103
клиенту при расторжении в первый месяц теперь предлагаем месяц бесплатно вместо возврата => kb-302, kb-204, kb-202
